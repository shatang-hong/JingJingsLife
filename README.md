# JingJingsLife-角色内核 · 设计分享

> 整理自 [JJsLife设计原稿/README](JJsLife设计原稿/README.md) 与 01–30 正式文档（定稿 2026-10-23）。

本项目是基于内核，而不单纯是记忆，记忆只是分支。另外对于大家关心的记忆库，我希望大家知道一件事，优秀的记忆库不是把内容记录全面，而是选择性优化记忆，只存不优化那就变成仓库了。

## 一、它是什么

把 AI 从「寄生在某个聊天软件上的机器人」，变成**独立于渠道存在的角色**。

判断标准只有一条：

> **关掉所有渠道之后，它还存在吗？还在变化吗？**

机器人和角色的差别就在这：

| | 机器人 | 角色 |
|---|---|---|
| 关掉渠道 | 就没了 | 还在，只是暂时收发不了消息 |
| 记得多久 | 一个会话窗口 | 按月、按年 |
| 换渠道 | 重写一个 | 加一层适配 |

所以目标不是「回复得更聪明」，而是**没人跟它说话的时候，它仍然在发生**。

## 二、三块东西，一条边界

| 谁 | 管什么 | 明确不管 |
|---|---|---|
| **内核** | 注意力、存储所有权、调度、通道 | 不推理、不看语义、不写一个字 |
| **DSH**（推理后端） | 推理、整理记忆、演化人格、调工具 | 不拥有数据，只是租户 |
| **渠道适配层** | 协议转换、收发、能力声明 | 不含任何角色逻辑（没有路由、没有人设、没有回复决策） |

这条边界划得狠，但理由很直白：

- **内核不推理**，所以它可以是一个不会思考的普通程序。让它做记忆提取，等于在里面重写一个更差的 DSH。
- **DSH 不拥有数据**，所以它可以换、可以升级、可以换代。数据在别处，它只是来干活的。
- **渠道是薄层**，所以换渠道就是停一个进程、起另一个，内核一行不改。

一句话：**内核给分寸，DSH 给话，渠道给通路。**

## 三、四条不变式

地基就这四条，违反它们的设计就是设计错了，而且后期修不回来。见 [01-不变式](JJsLife设计原稿/01-不变式.md)。

| | 是什么 | 违反会怎样 |
|---|---|---|
| **I1** | 记忆的处理归 DSH，存储与所有权归内核 | 数据绑在会话上，会话一过期角色就没了 |
| **I2** | 注意力归内核，而且只有一个 | 角色成了并行处理器，不再有「此刻」 |
| **I3** | 内核不推理，只掌握「此刻」和「东西在哪」 | 内核膨胀成一个更差的 Agent 运行时 |
| **I4** | 一切状态可演化，而且演化分速 | 全可变则失我，全不可变则成木偶 |

两个最容易读错的地方：

**「存储所有权在内核，写入权租给 DSH」**——这是 I1 的全部内容。内核管存在哪、谁能写、怎么快照、怎么打包带走；DSH 管记什么、怎么写、怎么整理。内核不理解内容。

**「串行的是注意力，不是上下文」**——I2 明确禁止所有渠道共用一个 session。每个人、每个群各有自己的会话，同一时刻只有一个在活跃。能共享的只是**状态**（体验块、事实便签），不能是**流水**（对话上下文）。理由有四笔账：串味、成本量级、人格侧面失效、隐私失效。见 [02-决策记录](JJsLife设计原稿/02-决策记录.md) 的 D6。

I4 还有一条修正：不可演化的有两类。`baseline.md` 是**限制**（不能做什么），`core.md` 是**定义**（我是谁）。两者都得显式枚举——没写进去的，早晚都会被演化掉。见 [19-身份分层](JJsLife设计原稿/19-身份分层.md)。

## 四、一条消息从头到尾

整套架构看着模块很多，主线其实只有一条。这条链就是 PoC 的阶段 A。

1. **进来**：适配器 `POST /ingest`，带上渠道、会话、发送者、是否群聊、文本、媒体、引用。
2. **认人**：内核查 `by_identity`（通道:uid → 节点），O(1)。这是每轮第一件事。
3. **硬规则**：私聊、直接 @ 我、回复我的消息 → 必须投递。结构可判，不给判断权。
4. **排队**：进注意力队列，严格单会话，其余会话的上下文冻结。
5. **交接**：`deliver` 推新消息 + 时钟事实 + 事实视图 + 在场视图 + 输出规格。只推增量，历史由 DSH 自己持有，只在第一次进入时 bootstrap 一次。
6. **想**：DSH 在自己那个会话里推理，需要时自己查 `memory.*`、`knowledge.*`。
7. **回报**：`reply` 带回回复（说话 / 沉默 / 表情）、当前 token 用量、可选的事实便签和体验块。
8. **发**：先发送，再写记忆。顺序不能反。
9. **落地**：适配器照着 `segments` 和 `delay_ms` 执行，内核记本轮。
10. **空下来**：队列为空、静默超过阈值 → `idle` → 整理会话开始回想。

几个值得单独记住的点（都在 [05-内核接口形状](JJsLife设计原稿/05-内核接口形状.md)）：

- **片段 ≠ 一轮。** `episode` 是一次注意力占用（进入某会话到离开），`turn` 是一次推理。写入挂在轮上，归档挂在片段结束加闲暇。之前一直混，就是把注意力单位和推理单位压在同一个词里。
- **四个动作**：`deliver` / `reply` / `idle` / `compact`。工具调用不算动作——动作决定「什么时候想」，工具决定「想的时候能查什么」。
- **实测修正**：`session/prompt` 只返回 `{accepted: true}`，不返回回复，所以「一次同步往返」不成立。PoC 的取回方式是文件轮询（500ms–1s 读到 `turn/end`），`/stream` 是性能优化，不是能不能做的前提。
- **白送的两样**：`requestId` 天生是幂等键，重投不会产生两条消息；`mode: queue / steer` 已经把「打断」做在协议里了。
- **改接口时的判据**：凡是内核需要「理解内容」才能决定的，都不该出现在接口上。接口上只留时间、来源、路径、配额、匹配结果。

## 五、各部分怎么做的

### 记忆：三个目录，一个工作台

三种载体，不是三个系统，是三个目录，共用同一套存储、工具、调度和版本：

| | 存什么 | 特点 |
|---|---|---|
| [relations/](JJsLife设计原稿/07-关系网络.md) | 关系的**当前状态** | 会被覆盖，只留最新 |
| [knowledge/](JJsLife设计原稿/18-知识库.md) | 跟具体人无关的**知识** | 可检索，带来源 |
| [memory/](JJsLife设计原稿/10-长期记忆条目.md) | 发生过的**事**、关于人的**事实** | 只追加，整理时重写 |

一句话：**关系是「现在怎样」，记忆是「曾经怎样」，知识是「普遍怎样」。**

中间还夹着一层，是这套设计特有的：**实时记忆**（[03](JJsLife设计原稿/03-实时记忆.md)）。长期记忆慢、摘要；会话上下文短、只管这一个对话。中间那段空档，角色原本是断片的。`runtime/realtime.log` 就是补它——全局唯一、只追加。

它只写两类东西，而且必须分开：

- **体验块**：位置、情绪基调、未完成的事、被打断的念头。每轮可选，内核只留最新一条。四项全是体验，没有一项是内容，所以既不会串味，也不撑上下文。它保住的是**在场感**：切到另一个会话时，知道刚才从哪来。
- **事实便签**：比如「A 说：明天聚会取消」。有事才写，多数轮次是空的。

读取上是一份数据两个投影：在场视图取最新体验块，事实视图取最近 N 条便签；`from_session` 顺手兼任注意力快照，不用另存一份。

**并发在这里自动消失**：同一时刻只有一个会话活跃，天然单写者；其余会话休眠，天然单读者。所以「禁止并发写」不是要写的机制，而是一条不变式。

三条关键判断：

1. **不做衰减曲线。** 遗忘首先发生在编码阶段——没留意的根本没进记忆。压缩就是衰减：压掉就没了。不需要算法，也不需要反向的重要度权重。只留两个客观信号：写入时给的 `importance`，和内核纯计数的 `recall_count`。判断归 DSH，内核只做 +1。
2. **结构找得到，语言读得懂。** frontmatter 可物化（时间、类型、人物、重要度），正文必须是自由文本，不要求格式统一。正文也拆成字段，记忆就变成数据库记录——它记得事实，却不记得经过，那是木偶。
3. **只追加是实时记忆的事，不是长期记忆的事。** 长期记忆得整文件重写加写前快照，否则没法「把三件小事合并成一件大事」，而那正是整理的核心动作。安全靠单写者加快照，不靠追加。

文件组织：活动区按主体加月份（整理时要按人聚合），归档区按时间（回溯时按时间翻）。一条记忆只存一处，多路索引（人、类型、月份、会话）全是派生的，丢了重扫即可。

### 关系：是图，不是名单

关系网络不是为了「登记有谁」，是为了**说明人和人之间怎么回事**，同时给 AI 用（据此表现）和给管理员用（审阅、认领）。见 [07](JJsLife设计原稿/07-关系网络.md) 和 [15](JJsLife设计原稿/15-主体与群.md)。

三个成分：节点（人或者群）、边 A（角色→他）、边 B（他↔他）。

边 B 容易被省掉，但必须有——角色得知道「张三和李四是夫妻」才能在群里说话不出错。这是**社交常识**，不是记忆。只有边 A，它就只懂「我和每个人什么关系」，不懂「他们之间什么关系」，那它不是在社交，只是在应答。

几条硬规则：

- **真源只有两处**：`nodes/person|group/<id>.md`（人和 DSH 都在编辑，所以要一文件一人）和 `graph.jsonl`（只由程序追加，所以整一个文件就行）。判据是**谁来维护**，不是文件多大。人维护的东西要碎，机器维护的要整。
- **`by_identity` 是热路径上唯一的强制依赖**。每来一条消息，第一件事就是「这是谁发的」，必须 O(1)。图解决「找到之后怎么走」，索引解决「怎么找到」——索引是图的入口，不是替代。
- **认领是关系层的联结，不是数据搬迁**。只让两个渠道身份指向同一个 node，不搬任何记忆，所以可撤销、无副作用。而且**冲突时默认拆开**：宁可当成两个人，不能当成同一个人——错分可修，错合是隐私事故。
- **`source` 决定这话能不能当事实说**。`inferred`（自己猜的）不能当事实用；`web`（网上搜的）必须说「我查到……」，不能说「就是……」。这条写死，否则它会把猜测当真相说出去。
- **`overrides` 存偏移，不存绝对值**。存绝对值的话，基础关系从 0.6 涨到 0.8，这个场合的表现纹丝不动——人格就分裂了。

### 人格：数值 → 档位 → 行为集

关系里只有 `closeness: 0.6` 这种数，它说出来的是话。中间缺一层映射，这层设计错了就落进两个坑：连续映射（每次措辞都不同，人设飘）或者粗量化（±0.01 永远看不见，「养成」等于没有）。见 [09-人格侧面投影](JJsLife设计原稿/09-人格侧面投影.md)。

```
数值（连续，DSH 微调）
  ↓ ① 阈值量化（内核，纯规则）
档位（离散，schema 定义）
  ↓ ② 查表（内核，纯规则）
行为集（可枚举的约束）
  ↓ ③ 拼接
注入 → DSH 表现
```

三步全是比大小、查表、拼接。**内核是个只认识这三件事的解释器，schema 是它执行的程序。**

由此得到最硬的一条：

> **凡是描述角色的东西，都不能写死在代码里，必须是数据。**

维度定义在 `relations/_schema.yaml`：键、类型、阈值、档位、行为集、是否启用、滞回死区。加一个维度就是加一条数据；停用一个就是 `enabled: false`，历史值留着。所以「定死三个维度」被否决了——不是三个太少，是**有几个不该由代码来决定**。

几个细节：

- **产物是行为集，不是形容词。**「可主动开话题 / 可提起上次聊的事 / 可叫『老张』 / 不问私事」可枚举、可测、可复现；「你现在跟他很亲近」不可测。
- **离散不是妥协。** 今天比昨天熟 0.001，谁也看不出来；跨档那一刻行为才明显改变——之前所有积累就是为了这一次跳变。
- **滞回防抖**：升档要过「阈值 + 0.02」，降档要跌破「阈值 − 0.02」，中间是死区。关系不会因为一次小事立刻改。
- **禁区不参与量化。** 无论多亲近，`boundaries` 里的东西永远是禁区，优先级高于一切行为集。
- **演化分三速**：数值（天级，DSH 每轮）／维度集合（月、年级，DSH 提议加管理员点头）／行为映射与人格文本（周、月级，改前快照）。维度演化的触发条件是「发生了现有维度解释不了的事」，不是「过了多久」。

初始启用四个：亲疏、正式度、信任、位差；另有六个备选，总量建议不超过 12。不全开的原因是每个维度每轮都要算、都进 prompt，而且维度一多行为互相抵消，反而看不出差异。**不是维度越多越像人，是维度越准越像人。**

**在群里怎么办：用熟悉度 κ 加权。** 在群里说话不是对张三说，是**当着所有人对张三说**，内容得对在场最保守的那个人也过得去。但「全场」不等于「全体成员」——500 人的群日常说话的只有 5 个。

```
κ = 在场活跃成员里熟人的比例
亲疏、正式度 = κ · 对他 + (1−κ) · 对这个群
信任 = min( κ · 对他 + (1−κ) · 对这个群 , 这个群的信任上限 )
```

加权在数值层做，量化在档位层做——所以插值完还是落回真实档位，不存在「半正式」这种状态。信任单独取上限，是因为**能不能说私事，由在场最不可信的人决定，潜水的也算**。

### 整理：闲时回想，不是后台任务

常见做法是定时跑个后台 job 清洗数据。这里不是。这里是：**没人说话的时候，它自己回想一会儿**。差别不只是说法——时间由闲暇给而不是 cron，**必须能被打断**，产物里多一段自述。见 [11](JJsLife设计原稿/11-整理会话.md) 和 [04](JJsLife设计原稿/04-时钟与闲暇.md)。

触发条件就一个字段：队列空 + 当前会话静默超过阈值。这个 `idle` 同时是时钟里的一个字段（它知道自己多闲）和整理的开关。一个字段兼两职，这就是「不需要 cron」的原因，而且天然出来「今天很忙没空想」「今天很闲想了很多」的差别——定时器给不了。

四级，差别不在工作量，在**视野**：

| 级 | 什么时候 | 看什么 | 回答什么 |
|---|---|---|---|
| L0 | 每次闲暇 | 实时记忆 | 刚才那些，有什么该记住的 |
| L1 | 每天 / 上下文快满 | 单个会话 | 这段对话，还剩什么值得留 |
| L2 | 每周 | 本周全部记忆 | 这一周发生了什么 |
| L3 | 每月 | 上月全部含归档 | 这一个月，我变了没有 |

**日看事件，周看片段，月看趋势。** 只有月度有足够视野看见「变化」本身。

三条顺序不能反：

1. **L1 是「先落盘、再压缩、后校验」。** 不是去控制压缩删什么（控制不了），而是让重要的东西在压缩之前就已经不在上下文里了。压掉的只剩本来就不打算留的。
2. **答应过的事要先扫再合并。** 合并会把多条记忆压成一条，`promise` 的截止条件最容易被压扁。
3. **清空实时记忆是内核干的**，DSH 只说「我归档完了」。不可逆的动作，交给不会误判的一方。

几个很有人味的设计：

- **周记月报：上限 3000 字，下限 0，内容没要求，可以不写。** 强制每周都写，它会开始编；编出来的比空白更假。空白本身就是信息——这周没什么值得记的。
- **整理不是静默的数据处理。** 独处时它会自言自语，这些话写进 `memory/journal/`，就是它**没有对话对象时说的话**。一个只有被呼叫时才存在的东西，不是人。
- **分片是「一次只想一个人」。** 整理要读这一片全部记忆，装不下——这是物理上限，不是优化问题。但它恰好和人回想的样子一样：没人会同时回想所有人。L3 按人跨月分片，进度落在 `runtime/maintenance.json` 的 `cursor`，断了从这接。
- **排队排的是「谁先被想起」，不是「谁更重要」。** 依据是距上次整理多久、最近活不活跃、有没有欠着的承诺、数据有没有冲突。重要性判断归 DSH。


### 数据放在哪

这一刀决定「打包带走」到底带走什么。见 [06-角色数据契约](JJsLife设计原稿/06-角色数据契约.md)。

| | 是什么 | 能带走吗 |
|---|---|---|
| 本体 | 人格、记忆、知识、关系、安全基线、表情库 | 能，这就是角色 |
| 运行状态 | 实时记忆、时钟、注意力、会话映射、原始图片 | 不能，换环境就失效 |
| 渠道绑定 | 账号、白名单、token、路由 | 不能，属于渠道 |

```
character/                 ← DSH 的工作区，可读可写
├── identity/              manifest / baseline(L0) / core(L1) / persona(L2·L3)
├── memory/                core · people · groups · topics · journal · archive
├── knowledge/             sources · notes · candidates
├── relations/             nodes · graph.jsonl · _schema.yaml · _index
├── assets/stickers/       candidates · approved
├── media/                 内容寻址，短期
├── runtime/               realtime.log · clock · attention · queue · maintenance
└── sessions/

ops/                       ← 在工作区之外：DSH 只读
├── audit/                 安全审计，长期，不记原文
├── logs/trace/            链路日志，滚动 7 天
└── snapshot/
```

> **写保护靠位置，读保护靠内容。**

于是「审计不记原文」从补充条款变成了主防线——否则内核拦下的东西，DSH 转头就能从日志里读回来。

格式也不是教条地「一切皆 md」，判据是**给谁看**：人也要看、模型也要看的（人格、记忆、知识、关系）用 md；纯机器状态（时钟、注意力、映射、索引）用 json。还有个隐藏理由——**格式本身就是权限暗示，可读的文本会被当成可改的**。时钟写成 md，模型就会想去编辑它。

另外两条：`format_version` 哪怕恒为 1 也得现在就有（典型的「现在不做，以后无解」）；快照照抄 dsh-rewind 的思路——写前备份、不变不存，单文件快照兜「写坏一个文件」，每日目录快照兜「大面积损坏」。回滚由内核执行，那是管理员动作，不是角色的行为。

### 说话的样子

说什么不够，**形式是「像人」的另一半，也更容易露馅**。见 [21](JJsLife设计原稿/21-输出形式.md)。

六个参数分两类：随场合变的是**分寸**（长度、分段、延迟、表情密度），角色固有的是**口音**（标点风格、语气词）。延迟是人味最大的开关：打字按 80–150ms/字，加上斟酌时间（越正式越慢），再抖 ±30%。超过 8 秒就折成「正在输入」，超过 30 秒干脆立即发。

> 延迟是为了像人，不是为了折磨人。

内核给的是**建议**不是硬限制，因为内容优先级高于形式：40 字装不下就该超。**适配器不决定节奏，只执行节奏**——渠道知道怎么发，不知道等多久。

**什么时候不说话**（[26](JJsLife设计原稿/26-社交默认值.md)）：设计允许沉默，但它几乎总会回。要解决的是「什么时候沉默是合适的」，答案是一组判据，不是概率。

| 层 | 内容 |
|---|---|
| 硬规则（内核） | 私聊、直接 @ 我、回复我的消息 → 必须投递 |
| 判据（DSH） | 群里别人在聊没点我 / 已经有人答充分 / 对方在抒情绪 / 我无话可说 / 场合不适合 |
| 档位（人格） | `social_prior.silence_level` 四档：有问必答、谨慎、**自然**（默认）、多听少说。只调门槛，不调概率 |

再内向的角色，也不该让私聊的人干等。

「接续」是**被动**的：下次进这个节点时，如果体验块的「未完成」还写着，就提示一句。主动回去找话属于主动聊天，本来就不做。放弃也是一种接续——重要的下次自然会提，过期的留在记忆里。

### 出故障的时候

判据能成立，是因为**渠道和推理是解耦的**（[17](JJsLife设计原稿/17-故障与降级.md)）：

| 断了什么 | 数据 | 思考 | 整理（变化） |
|---|---|---|---|
| 渠道 | 在 | 在 | 照常 |
| DSH 或模型 | 在 | 没了 | 停 |

所以「关掉 QQ 它还在」有三种理解，只有一种是要的：不是进程没退出，也不是数据还在磁盘上，而是**它还在回想、还在变**。

三条规则：

- **先发送，后记忆。** 反过来的话，写完记忆发送失败，记忆里就有「我说了 X」但实际没说——它会引用一句从未发生的话。**没发生的事不该成为记忆。**
- **过期消息不回，但记一笔。** 5 分钟内正常回；5 分钟到 2 小时不回但记进记忆；超过 2 小时只记「错过了」。这跟「不想回」不是一回事——它不是不想，是**回得不对**。
- **故障不该让它变得不像自己。** 不能推理就沉默，别拿模板假装；数据继续留；恢复后不假装没事。最差的做法是降级成规则机器人，那会让对方觉得「它已经不在了」，正好是第一判据要否定的。

### 安全与治理

**安全是三层，不是二选一**（[03](JJsLife设计原稿/03-实时记忆.md)）。判据就一句：这条信息是「有形态」还是「只有语义」？

| 层 | 在哪 | 拦什么 | 靠不靠得住 |
|---|---|---|---|
| L1 不可变基线 | prompt 里，DSH 改不了 | 语义类：政治、隐私、底线 | 软，能被诱导，但只有它能处理语义 |
| L2 确定性拦截 | 内核，写入前 | 形态类：密钥、路径、证件号、已知串 | 硬，绕不过 |
| L3 输出兜底 | 内核，出站前 | 已知的高危表达 | 硬，但只兜已知的 |

> **能判断的交给判断，判断不了的交给规则。**

两个反直觉的地方：语义类最好的拦截点是**让它不产生**，不是拦下来——等它输出完，内核已经没判断能力了；拦截结果**不要回告 DSH**，否则它可能来一句「刚才想说的被拦了」，等于二次泄露。界限得承认：能保证「尽量不产生」加「已知的必拦」，保证不了「未知的也拦」。

**身份分层**（[19](JJsLife设计原稿/19-身份分层.md)）：不可变性不能是二元的，得分层——越抽象越不可变，越具体越可变。安全基线绝对不可变（它是限制），身份内核不可替换（它是定义），人格表现周月级可演化，浅层观念随环境变。

真矛盾的地方在中间那层，答案是：**核心不可替换，但可以被重新诠释。**

- 可以写：「我意识到我的友善有时候是在回避，我在学着直接一点」
- 不能写：「我其实不在乎别人怎么样」

反面例子说明为什么需要这层：四十周里每周都做对一步，合起来却成了另一个人。**它不是防某一次错误，是防无数次正确叠加成错误。**

**治理五件事**（[22](JJsLife设计原稿/22-运行与治理.md)）：租约决定谁在写，预算决定写多少，生命周期决定写到什么时候，多角色决定写到哪个目录，隐私决定能不能擦干净。

- **租约不是文件锁。** 文件锁崩了可能不释放，也不知道持有者死活；租约带过期时间，天然处理假死。拿不到就**只读启动**，GUI 上写一句「另一个实例在跑」。
- **三份预算分开记**：对话、整理、检索。混在一起要出事——一次月度整理吃掉整月额度，后面几天角色就「失语」了。超了不能硬截断，按序降级：缩事实条数 → 减知识检索 → 缩输出长度 → **绝不动人格和身份**。
  > 为了省钱牺牲「它是谁」，等于用最贵的方式毁掉这个项目。
- **成本约束可以变成作息**：宽裕时话多愿意展开，紧张时回得短、少接话、偶尔「嗯」。人累了也这样——不是缺陷，是把资源约束翻译成了性格。
- **退役三态**：停用（还在生活）／封存（睡着了）／销毁（真没了）。销毁有 2 天冷静期，期内进 `_trash/` 可恢复，到期只留一条没内容的极简记录。
- **隐私只做三件事**：能删（删所有引用并给可核验报告）、能导出、**不骗人**（写进基线：不主动宣称自己是人）。对话者自助删除不做——技术上验不了身份。

**日志**（[13](JJsLife设计原稿/13-日志与可观测.md)）：两类不能合并，关键差别是**可删性**——链路日志滚动删除，审计绝不可删。合成一个文件，「日志会滚动」这条早晚把审计一起删掉。（原文这里有处不一致：13 把审计放 `character/audit/`，06 和 25 放 `ops/audit/`。以后者为准，不然写保护不成立。）

占位符也别只写 `<redacted>`，用 `<msg sha256:a3f1 len=42>`——既判断得出两条日志是不是同一条消息，又不泄露内容，还看得出有没有被截断。容易漏的不只是正文：昵称、群名、记忆正文、模型输出、检索词都要占位。

> **日志只记结构和标识，不记内容。**

它得能回答三个问题，否则不够用：**这条消息为什么没回？它为什么不知道这件事？它为什么突然变冷淡了？**

### 渠道与管理入口

**渠道是独立进程、可插拔**（[23](JJsLife设计原稿/23-渠道适配.md)）：语言无关（QQ 用 Node 直接复用现成的）、崩溃隔离（适配器挂了不影响整理）、可热替换。

三条边界：内核不知道协议、账号体系、限流、能不能发多段；适配器不知道关系、人格、记忆、**回复节奏**、谁是谁；**会话到节点的映射归内核**，因为它依赖关系索引，那是内核的资产。

模块化真正的着力点不是「接口长得一样」，是**能力可查询、差异可降级**：适配器启动时声明自己支不支持图片、表情、撤回、正在输入、连发多段、单条多长。缺分段就把段拼回一条；缺表情就把表情密度强制为无。**没声明的一律当不支持**——不用「默认支持、出错再说」，那会让问题在消息已经发出去之后才被发现。

还有一条决策值得记住：**不建在任何第三方 IM 插件之上**。看过的那个内置只有 MockChannel，方向还是「人指挥 DSH」，不是「角色参与群聊」。根本那条是——

> **角色活得比插件久。** 把命脉交给会随上游升级而变化的东西，等于给角色定了个短寿命。

但它的入站契约跟我们几乎同构，说明抽象方向是对的：**借鉴契约，不依赖实现。**

**管理入口两个，主次分明**（[14](JJsLife设计原稿/14-管理入口.md)）：GUI 是主界面，管理员 DSH 是兜底。

> GUI 处理**已知的问题**，DSH 处理**未知的问题**。

写操作全部收口到内核 API 一处，用 `actor` 字段区分来源（角色自己、管理员会话、GUI、系统）。这样审计只有一处、快照不会漏、基线校验不会漏。

管理员那边两条最容易忘：**不注入人设**，**不写角色记忆**——否则「管理员问了一句『你还好吗』」会变成角色记忆里的一次真实对话。还有个真实风险：管理员会慢慢变成角色（读了人设和最近说的话，不自觉带上那个语气）。最有效的防线是输出格式——只允许「事实 + 建议」，禁止第一人称感受，因为格式不允许出现「我觉得」，模型就少了一条滑下去的坡道。

工具面做物理隔离：角色会话只能看到 `memory.*` 和 `channel.send`，管理员才有那一套。不是没权限，是**根本没有这个工具**。

## 待定内容

- **压缩策略**：压缩对单轮的影响，只能真实使用中观察。
