## 一、三种冷启动

| 类型 | 从什么状态开始 | 关键问题 |
|---|---|---|
| **新角色** | 只有 `identity/` 三个文件 | 空的记忆与关系，第一句话说什么 |
| **新节点（人）** | 有此人的身份，无关系数据 | 默认档位是多少 |
| **新节点（群）** | 有群号，无任何观察 | 群属性怎么初始化 |

---

## 二、默认档位是人格的一部分，不是系统常量

这是本节最重要的判断。

新手常见做法：所有维度的初值都设 0.5，或者全设 0。

**两者都错**，因为：

> **「对陌生人的初始态度」正是性格的核心体现。**

| 角色性格 | 对陌生人的初始 `closeness` |
|---|---|
| 外向、热情 | 0.30 |
| 中性 | 0.15 |
| 冷淡、谨慎 | 0.05 |

所以默认值必须写在 `persona.md`（或 `core.md`）里，作为角色的初始设定：

```yaml
defaults:
  stranger:                    # 第一次接触的人
    closeness: 0.15
    formality: 0.60
    trust: 0.20
  new_group:                   # 第一次进的群
    closeness: 0.20
    formality: 0.70
    trust: 0.15
    safety: 谨慎
```

这样**两个不同的角色开箱就不同**，而不是先一样、再靠演化分开。

### 2.1 为什么不用 0

`closeness: 0` 意味着「完全不认识且不打算认识」，行为集会输出「不主动、不提问、只答」。

但真实的人对陌生人不是这样——**至少会礼貌地接话**。

所以初值应该是一个「礼貌但疏远」的状态，不是一个零点。

## 三、第一次对话要明确告知

新节点第一次收到消息时，注入里必须包含一条事实：

```
这是你第一次和这个人说话。
```

不加这条，角色会**装作认识**——因为它看到的只有"张三：你好"，没有别的线索，而模型倾向于补全语境。

同类事实还有：

| 场景 | 注入 |
|---|---|
| 首次该节点 | 这是你第一次和这个人 / 这个群说话 |
| 长期未联系（> 30 天） | 你们上次说话是 47 天前 |
| 角色刚诞生 | 你刚开始存在，还没有任何记忆 |

> **角色必须知道自己「不认识」，否则它会假装认识。**

---

## 四、新群的属性初始化

群属性和人的关系不同——**群在角色进来之前就已经存在了**。

三层获取顺序：

| 顺序 | 来源 | `source` | 说明 |
|---|---|---|---|
| 1 | 群名称推断 | `inferred` | 「XX技术交流群」→ `formality: 0.7`，置信度低 |
| 2 | 观察发言 | `observed` | 几天后覆盖推断（15 的 8.8） |
| 3 | 向熟人打听 | `stated` | 角色在私聊里自然地问「你们那群平时聊什么」 |

第 3 条不需要特殊机制——它就是**一次普通的对话**，产出一条 `type: fact` 的记忆，整理时归到群节点。

### 4.1 缺省兜底

如果什么都拿不到：

```
formality: 0.7   # 偏正式
safety: 谨慎      # 少开玩笑
```

> **不知道的时候，往保守那边倒。** 这与 15 的 8.9（trust 设群上限）同一个思路。

## 五、空记忆时不要空转

新角色没有任何历史，但闲暇触发照常（04 的 D5）。

问题：整理一个空角色做什么？

规则：

> **实时记忆里没有内容，就不触发整理。**

否则角色会每天"回想"一次空白，纯烧钱。

### 5.1 唯一例外：诞生时的第一条记忆

角色第一次启动时，写一条 `type: event` 的记忆进 `memory/core/`：

```yaml
type: event
when: <创建时间>
session: system
people: []
importance: 1.0
source: admin
---

我开始了。这是我知道的第一件事。
```

这条不是装饰——它给了角色一个**时间原点**。

之后所有的"多久之前"都相对它计算，整理时的自述也有了参照（「我存在了 47 天」）。

---

## 六、第一次整理做什麼

新角色首次整理（可能几天后才触发），没有历史可合并，但有别的事可做：

| 动作 | 说明 |
|---|---|
| 确认 `identity/` 三文件齐备 | `core` / `baseline` / `persona` 都在且 hash 正常 |
| 校验默认值已生效 | `persona.md` 的 `defaults` 能被读到 |
| 建空索引 | 让 `by_identity` 等索引可用 |
| 写第一条自述 | 「我刚被创建，还没有和谁说过话」 |

---

## 七、一个容易漏的边界：自己有多个身份

如果角色同时接了 QQ 和微信，第一次在微信收到消息时：

- 它记得 QQ 上的人（如果已认领）
- 但**这是它第一次用微信**

所以注入需要区分两层：

| 层 | 内容 |
|---|---|
| 关系层 | 「你认识张三，关系是 X」 |
| 渠道层 | 「但你第一次在这个渠道和他说话」 |

不区分会导致角色说出「我们不是一直在微信上聊吗」这种话。

---

## 八、未决

1. **默认值能否按渠道不同**：微信偏正式、QQ 群偏随意，是否值得区分？
2. **「第一次」的判定粒度**：按节点还是按（节点 + 渠道）？第七节倾向后者，但会让状态变多。
3. **诞生记忆的文案**：谁来写？管理员还是模板？这其实决定了角色最初的语气。
4. **长期未联系的阈值**：30 天是否合适？会不会让角色对老朋友过于生疏？
5. **空角色被拉进群**：它应该先观察多久再说话？
