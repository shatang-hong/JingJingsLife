# 03 · 实时记忆

本文件是 D3.1 的展开：实时记忆的形态、写入语法、安全拦截。

---

## 一、定位

一个高频更新的临时工作台，充当所有会话共享的**工作记忆**。

它填补的是长期记忆与会话上下文之间的空档：

```
长期记忆（慢、摘要、永久）
      ↑ 归档
实时记忆（快、明细、会被清空）   ← 这一层
      ↑ 追加
会话上下文（仅本会话）
```

> 写完长期记忆之前的那段时间，原本角色是断片的。实时记忆补的就是这段。

---

## 二、形态

- **单一文件**，全局唯一
- **append-only**（追加），不是覆盖式修改
- 每条记录带：时间、来源会话、内容、可见范围（scope）
- 定期**归档**：沉淀入长期记忆后清空 / 轮转

### 为什么必须追加而非覆盖

1. 覆盖会丢——写者只记得最近的事，早先的就被抹掉
2. 追加天然是日志，可回溯、可审计
3. 追加与「单一写者」完全兼容，不存在冲突可能

因此准确表述是「高频**追加**」。一旦允许改写既有条目，冲突就必然出现。

---

## 三、并发问题在单注意力模型下自动消解

| | 常规设计需要 | 本架构下 |
|---|---|---|
| 并发写 | 文件锁 / 事务 | 同一时刻只有一个活跃会话 → **天然单写者** |
| 并发读 | 读写锁 | 其余会话处于休眠（上下文冻结）→ **天然单读者** |

所以「允许并发读、禁止并发写」不是一个需要实现的**机制**，而是一条**不变式**：

> **实时记忆永远只有一个写入者——当前占用注意力的那个会话。**

仍要写进文档的理由：将来若引入「主动聊天」与「被动回复」并行，这条不变式会立刻变成必须显式检查的护栏。

## 四、两个副作用：性质不同，处理者也不同

| 副作用 | 性质 | 处理者 |
|---|---|---|
| 隐私串味（该不该向外说） | **语义判断** | **DSH** |
| 与本会话重复（自己刚说过） | **结构去重** | **内核** |

### 1. 隐私串味

每条记录带 `scope` 标签，但**标签只提供属性，不提供禁令**。是否向外说由 DSH 判断，并受「设计权重」调节（默认倾向不说，有理由才说）。

> 这个「设计权重」与 [26-社交默认值](26-社交默认值.md) 的 social prior 是同一个东西——对内是「说不说」，对外是「能不能转述」。

理由：人也是这样。人不会因为知道某件事就机械守口如瓶，也不会因为它是秘密就永远缄默。硬过滤会让角色在该开口时张不开嘴。

### 2. 与本会话重复

记录带 `from_session`，内核装配时按 `来源 == 当前会话` 机械剔除。

这不是隐私判断，只是去重，纯匹配，不构成推理。

## 五、安全拦截：三层，不是二选一

### 5.1 有一类信息不给判断权

第 4 节的「交给 DSH 判断」仅限**可判断的私密**。另有一类必须由内核硬拦截：

| 信息类别 | 处理 |
|---|---|
| 凭据、密钥、本机路径 | 写入层直接拒收 |
| 安全敏感信息 | 同上 |
| 政治敏感内容 | 同上 |
| 个人敏感信息（真实身份、住址、联系方式等） | 同上 |
| 安全基线内容 | 不可转述、不可演化（**注**：DSH 对工作区外可读，所以「不可读」不成立，见 [02](02-决策记录.md) 的 D4.1） |

原则：

> **可判断的交给判断，不可判断的交给规则。**

与人格文件的不可变基线校验是同一个模式。

### 5.2 三层分工

判据只有一条：**这条信息是「有形态」还是「只有语义」？**

| 层 | 位置 | 拦什么 | 可靠性 |
|---|---|---|---|
| **L1 不可变基线** | prompt 内，DSH 不可改 | 语义类（政治、隐私、底线） | 软，可被诱导，但是唯一能处理语义的手段 |
| **L2 确定性拦截** | 内核，写入前 | 形态类（密钥、路径、证件号、已知串） | 硬，不可绕过 |
| **L3 输出兜底** | 内核，出站前 | 已知高危表达 | 硬，但只能兜已知的 |

L1 是 **DSH 的依据**（告诉它什么不能说），L2 / L3 是 **内核的闸门**（真正执行丢弃）。

**为什么不能全给内核**：内核只能做形态匹配。全给内核 = 变成一个规则引擎，语义类必然大量误杀（「政治」二字出现在学术讨论里）和漏杀（换个说法就绕过）。

**为什么不能全给 DSH**：DSH 可被诱导，且没有强制力。它的「自觉」不是防线，只是倾向。

### 5.3 反直觉的一条

> **语义类最好的拦截点是「不产生」，不是「拦下来」。**

DSH 是生成方，等它输出后，内核已经没有判断能力了。所以 L1 才是语义类的主防线，L2 / L3 只是兜底。

**要诚实承认的界限**：能保证的是「尽量不产生」+「已知的必拦」，不能保证「未知的也拦」。

### 5.4 两条静默要求

1. **拦截结果不回告 DSH**。否则 DSH 可能在回复里说「我刚才想说什么被拦了」，等于二次泄露——用户知道了哪句话踩线。
2. **审计日志不记原文**，只记「发生了一次拦截」（时间、会话、类别）。且日志目录 DSH 无读权限。

## 六、写入语法（便签协议）

### 6.1 三个视角，一个东西

| 视角 | 是什么 |
|---|---|
| **实时记忆** | 介质（那个文件） |
| **便签协议** | 写入语法（怎么往里写） |
| **注意力快照** | 读取形态（会话开始时怎么用） |

只实现一次。

### 6.2 谁判定「值得写」

- 不能让内核判定（违反 I3）
- 不能让 DSH 每轮多跑一次判断（成本）

**答案：用协议标记，复用既有机制。**

沿用 WeChatAgent 已在使用的 Reply Protocol（`RESPOND:` / `SILENCE` / `[STICKER:S1]`），增加一种输出标记。内核只做**模式匹配与分发**，不做语义理解。

这样：

- 零新增推理
- 与既有协议解析代码同构
- 判定权仍属于 DSH（符合 I1）

### 6.3 写入分两类（关键区分）

| 类型 | 内容 | 频率 | 是否节流 |
|---|---|---|---|
| **体验块** | 「刚在 A 群，聊得挺轻松，有件事没说完」 | 每轮可选输出，内核保留最新一条 | 不节流 |
| **事实便签** | 「A 说：明天聚会取消」 | 有事才写 | 节流，多数轮次为空 |

**为什么必须分开**：

- 若只有事实便签且节流 → 「A 说了一句无关紧要的话」不留任何痕迹，角色切到 B 时不知道刚才在跟 A 聊天，**在场感丢失**。
- 若为保住在场感而取消节流 → 实时记忆退化为全量日志，撑爆读取预算。

### 6.4 体验块的四项内容

| 字段 | 例 | 作用 |
|---|---|---|
| 位置 | 刚在 A 群（10 分钟前） | 注意力坐标 |
| 情绪基调 | 那轮聊得挺轻松 | 余温 |
| 未完成 | A 问了个问题，我还没答完 | 悬念 |
| 意图残留 | 我刚想补一句关于装修的 | 被打断的念头 |

> **四项全是「体验」，没有一项是「内容」**——所以不会导致串味，也不撑上下文。

### 6.5 一条记录的字段

```
{ ts, from_session, scope, text, ttl, type }
```

| 字段 | 作用 | 谁使用 |
|---|---|---|
| `type` | `presence`（体验块）/ `fact`（事实便签） | 内核分流 |
| `from_session` | 来源会话 | 内核按此**去重**（结构性） |
| `scope` | 属性标签（私聊 / 群聊 / 可共享） | DSH 据此**判断**可否转述（语义性） |
| `ttl` | 过期时间 | 内核清理陈旧条目 |

### 6.6 读取策略：一份数据，两个投影

| 投影 | 取什么 | 用途 |
|---|---|---|
| 在场视图 | 最新一条 `presence` | 「我刚从哪来」 |
| 事实视图 | 最近 N 条未过期的 `fact` | 跨会话事实同步 |

**结论：存储合并、写入分治、读取分投影。**

这样既消除两处不一致，又不让注入成本随规模线性增长。

### 6.7 一物两用

`from_session` 同时充当「注意力快照」的载体——DSH 读到「来源：A 群，10 分钟前」，自然知道「我刚从那边过来」，不需要再单独维护一份快照。
