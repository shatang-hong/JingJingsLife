# 09 · 人格侧面与自进化

> 上游：[01-不变式](01-不变式.md)（I4）｜ [07-关系网络](07-关系网络.md)

---

## 一、自进化是根本前提

这是「人」与「程序」的分界。程序只有配置，人有成长。

I4 的要求不是「数值能变」，而是**结构能变**：

| 层次 | 演化什么 | 若被硬编码会怎样 |
|---|---|---|
| 值 | 维度上的数值 | 只能变强变弱，**变不出新的自己** |
| **维度** | 有哪些维度、各自档位 | **自进化被锁死在预设框架内** |
| 结构 | 人格文本、行为映射表 | 人设固定，只是参数在动 |

所以一条硬约束：

> **凡是「描述角色」的东西，都不能写死在代码里，必须是数据。**

这直接否决了「定死三个维度」的做法——不是三个太少，而是**它不该由代码决定有几个**。

---

## 二、要解决的问题

关系里存的是 `closeness: 0.6` 这样的数，但角色要说的是话。中间缺一层映射。

这层设计错了会踩两个坑之一：

| 坑 | 表现 |
|---|---|
| 连续映射 | 每次措辞都不同，人设飘，不可复现 |
| 粗量化 | ±0.01 的微调永远观测不到，「养成」等于没有 |

---

## 三、三段式

```
数值（连续，DSH 微调）
  ↓ ① 阈值量化（内核，纯规则）
档位（离散，由 schema 定义）
  ↓ ② 查表（内核，纯规则）
行为集（可枚举的约束）
  ↓ ③ 字符串拼接
注入 prompt → DSH 表现
```

三步全是纯规则：比大小、查表、拼接。没有一步涉及理解内容，符合 I3。

**内核是一个只认识「比大小 + 查表 + 拼接」的解释器，schema 是它执行的程序。**

> 自进化 = 改写程序，不是改解释器。

---

## 四、离散不是妥协，是关系的真实形态

这是对「±0.01 观测不到」的回答：

> **不需要每次微调都被观测到。**

人的关系也是渐变的。今天比昨天熟 0.001，谁也看不出来。只有在**跨档**那一刻，行为才会明显改变——而之前所有的积累，正是为了那一次跨档。

你不会每天觉得「我和他更熟了」，但某一天你突然发现自己开始跟他讲私事了。

**微调连续积累，表现离散跳变。这恰恰是对的。**

---

## 五、映射产物是「行为集」，不是「形容词」

| 方式 | 例 | 结果 |
|---|---|---|
| ❌ 形容词 | 「你现在跟他很亲近」 | 每次表达都不同，人设飘 |
| ✅ 行为规则 | 「可主动开话题；可提起上次聊的事；可叫『老张』；不问私事」 | 稳定、可复现、可测 |

形容词不可枚举、不可测；行为规则可枚举、可测。

## 六、维度必须是数据（schema）

### 6.1 定义文件

`relations/_schema.yaml`

```yaml
version: 1

dimensions:
  - key: closeness
    name: 亲疏
    type: scalar                  # scalar | enum
    range: [0, 1]
    enabled: true
    hysteresis: 0.02              # 防抖死区
    levels:
      - { up: 0.20, label: 陌生 }
      - { up: 0.40, label: 认识 }
      - { up: 0.60, label: 相熟 }
      - { up: 0.80, label: 亲近 }
      - { up: 1.01, label: 亲密 }
    behaviors:
      亲近:
        - 可主动开启话题
        - 可提起上次聊过的事
        - 可追问细节
      亲密:
        - 可询问私人近况
        - 可表达自己的困扰

  - key: formality
    name: 正式度
    type: enum
    enabled: true
    levels: [正式, 中性, 随意]
    behaviors:
      随意:
        - 可用口语与省略语
        - 可使用表情
        - 可开玩笑

  - key: power
    name: 位差
    type: enum
    enabled: true
    levels: [下位, 平位, 上位]
    behaviors:
      上位:
        - 不使用命令式
        - 不主动调侃
```

### 6.2 这个结构解决了什么

| 需求 | 结果 |
|---|---|
| 新增一个维度 | 往 schema 加一条，不改代码 |
| 修改某档的行为 | 改 schema，不改代码 |
| 停用某维度 | `enabled: false`，历史数据保留 |
| 内核职责 | 读 schema、按 schema 执行，仍是纯规则 |

**这就是自进化的落地方式**：系统的「理解方式」可以变，而内核一行不改。

### 6.3 内核仍然不推理

有人会问：为了新维度去改 schema，算不算内核在做判断？

不算。**内核只解释，不决定**。

决定「要不要加这个维度」的是 DSH（观察互动）或管理员（拍板）。内核只是照着执行。

这也符合 I1 的分工：智能归 DSH，执行归内核。

## 七、初始维度集

维度开放，但初始总得给一组。以下是**候选池**，`enabled` 决定当前启用哪些。

| 维度 | 含义 | 理论来源 | 初始 |
|---|---|---|---|
| `closeness` 亲疏 | 情感距离、可共享的私人领域 | 差序格局 | ✅ |
| `formality` 正式度 | 语域正式程度 | 礼貌理论 | ✅ |
| `trust` 信任 | 可托付、可暴露脆弱的程度 | — | ✅ |
| `power` 位差 | 上 / 平 / 下位 | 权力距离 | ✅ |
| `directness` 直接度 | 直白 vs 委婉 | 礼貌理论的「强加度」 | ○ |
| `reciprocity` 人情 | 亏欠与回报的平衡 | 人情与面子 | ○ |
| `warmth` 热情度 | 情感外露程度 | — | ○ |
| `humor` 玩笑度 | 可开玩笑的空间 | — | ○ |
| `verbosity` 话量 | 说多还是说少 | — | ○ |
| `initiative` 主动度 | 主动找人说话的频率 | — | ○ |

✅ 初始启用　○ 备选，按需引入

### 为什么不一上来全开

| 原因 | 说明 |
|---|---|
| 成本 | 每个维度每轮都要算、都要进 prompt |
| 自然度 | 维度越多，角色越像「在意太多」的人，反而不像人 |
| 可观测性 | 维度一多，行为互相抵消，看不出差异 |

> **不是维度越多越像人，而是维度越准越像人。**

### 关于「一维温度计」的问题

即使只用四个维度，也解决了一维表达不了的问题：

| 关系 | 亲疏 | 正式 | 信任 | 位差 |
|---|---|---|---|---|
| 父亲 | 近 | 正式 | 高 | 下位 |
| 发小 | 近 | 随意 | 高 | 平位 |
| 客户 | 远 | 正式 | 中 | 平位 |

亲疏相同，其余三个维度把它们区分开了。

## 八、演化的三个层次与速率

一次性全速演化 = 精神分裂。真正的成长是分层的。

| 层 | 演化什么 | 谁推动 | 节奏 | 是否留痕 |
|---|---|---|---|---|
| **L1** | 维度上的数值 | DSH（每轮） | 天级 | 不需要（连续变化） |
| **L2** | 维度集合本身 | DSH 提议 + 管理员确认 | **月 / 年级** | **必须** |
| **L3** | 行为映射、人格文本 | DSH（整理时） | 周 / 月级 | 必须快照 |

### L2 为什么必须慢

人的性格结构很少变，但会在**重大经历**后改变。

- 太快 → 角色每周换一套性格，等于精神分裂
- 太慢 → 永远不会成长

判断标准不是时间，是**经历**：

> L2 的触发条件是「发生了现有维度解释不了的事」，不是「过了多久」。

典型触发：一次严重的误会、一个长期关系的性质改变、一次价值观冲突。

这类事件之后，角色需要新的维度来描述这个人——这正是「成长」的定义。

### 8.4 人工闸门：所有自动学习的产物都要过关

三个来源，一条规则：

| 产物 | 谁提议 | 谁批准 |
|---|---|---|
| 新维度 | DSH | 管理员 |
| 新表情 | DSH 收集（16） | 管理员 |
| 新黑话 | DSH 提取（qq-bridge 模式） | 管理员 |

> **新产出不等于直接生效。**

三条理由：

1. 这些是**表达方式**，影响外部观感，而且发出去收不回来
2. 自动学习的质量参差，闸门是唯一的质量控制点
3. 闸门本身就是「人与角色」的边界：**它学什么，由人决定**

代价是角色不能完全自主成长，始终有一个监护人。

但这不是缺陷：

> **在能承担后果之前，需要有人替它把关。**

这也解释了 L2 慢的真正原因——不是技术慢，是**重大改变必须有人点头**。

#### 闸门不是制度，是能力缺口的补丁

现在表情为什么必须逐条人工批？**不是因为不信任角色**，而是因为：

> 模型对图片的识别可能不准。识别错了还发出去，就是不可挽回的误会。

所以闸门的严格程度应该**跟着能力走**，而不是固定：

| 能力状态 | 闸门 |
|---|---|
| 识别不可靠 | 逐条人工批（当前） |
| 基本可靠 | 抽样审核 |
| 高度可靠 | 只保留撤回 / 举报通道 |

> **闸门存在的意义，是等能力长齐。** 它不是永久制度。

这条也适用于其他闸门：维度提议、黑话确认，都应在能力提升后逐步放宽。

## 九、约束：维度必须可观测

一条维度如果映射不出可观察的行为，它就没有存在意义，只是玄学。

| 约束 | 说明 |
|---|---|
| **必须绑定行为** | 每个维度至少映射一条可观察的行为 |
| **总量上限** | 建议 ≤ 12，超过就无法理解 |
| **可淘汰** | 长期无变化的维度设 `enabled: false`，不删除数据 |

第一条最重要：

> **不能映射行为 = 玄学 = 不该存在。**

这也是判断 DSH 提议新维度是否合理的第一道闸门——它必须能说出「这个维度会让角色在什么时候、说什么样的话」。

## 十、其他规则

### 规则 1：滞回，防止忽冷忽热

数值在阈值附近震荡（0.39 ↔ 0.41）会让角色今天热情明天冷淡。

- 升档：`> 阈值 + hysteresis`
- 降档：`< 阈值 - hysteresis`
- 中间是死区，保持原档

这也符合人：关系不会因为一次小事就立刻改变。

### 规则 2：`overrides` 存偏移，不存绝对值

若存绝对值，基础值从 0.6 演化到 0.8 时，这个场合的表现纹丝不动，角色在同事群永远一个样，**人格就分裂了**。

存偏移（`-0.2`）则场合表现自动跟随基础关系演化。

### 规则 3：`boundaries` 是硬约束，不参与量化

> 无论关系多亲近，禁区永远是禁区。

优先级高于一切行为集，不被「亲密档 = 什么都敢说」覆盖。

### 规则 4：最终表现 = 人格 × 关系

| 数据 | 回答 |
|---|---|
| `persona.md` | 「我是谁」——对所有人一样的基线 |
| `relations/*.md` | 「我对他什么态度」——因人而异 |

同一个角色，对陌生人也不该冷漠（那是性格），对亲近的人也不该失去分寸（那是教养）。

### 规则 5：称呼的演化要留痕

`address_as` 从「张三」变成「老张」，往往比 closeness 涨 0.1 更能说明关系变化。

建议：称呼改变时**记一条记忆**，而不是只更新字段。

因为称呼的转变是**事件**，不是**状态**。

## 十一、内核输出什么

内核不做措辞，只给分寸：

```yaml
projection:
  closeness: 亲近        # 档位，不是数值
  formality: 随意
  trust: 高
  power: 平位
  address_as: 老张
  boundaries: [不提前公司]
  source: observed
```

DSH 拿到档位与行为约束，自己决定具体怎么说。

> **内核给「分寸」，DSH 给「话」。**

## 十二、未决

1. **阈值初值**：各维度的档位边界现在都是经验值，需要真实互动数据校准。
2. **谁有权启用新维度**：完全由管理员确认？还是给 DSH 有限自主权（低影响维度可自行启用）？
3. **维度冲突**：`power: 上位` 与 `closeness: 亲密` 同时成立时（如亲近的长辈），行为集冲突怎么办？需要优先级规则。
4. **淘汰后的历史数据**：维度停用后，`relations/*.md` 里那些值保留还是清理？保留会变成死数据。
5. **跨档通知**：档位跳变时，要不要让 DSH 知道「关系刚变了一档」？可能让它表现得更自然，也可能让它过于自觉。
