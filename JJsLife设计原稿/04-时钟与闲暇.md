## 一、时钟

角色必须有时间感。但**时钟不能以数据形式注入，必须以事实形式注入**。

DSH 拿到 `1697000000` 没有意义；拿到 `{ now: "凌晨2:14", since_last_contact: "6天" }` 才有意义。

### 1.1 应提供的维度

| 维度 | 例 |
|---|---|
| 绝对时间 | 此刻是几点、星期几 |
| 相对时间 | 距上次联系多久 |
| 持续时长 | 这段对话已经聊了多久 |
| 节律 | 白天 / 深夜，工作日 / 周末 |
| 打断次数 | 这段对话被打断了几次 |
| **闲暇时长** | 上次说话到现在空置了多久 |

### 1.2 边界：内核给事实，DSH 给意义

| 谁 | 给什么 |
|---|---|
| 内核 | `since_last_contact: "6天"` |
| DSH | 「六天没联系意味着关系疏远了」 |

如果内核去生成「现在是凌晨两点你刚被叫醒」这句话，那内核就在推理了——违反 I3。

时钟是**关系演化的输入之一**，但不能由内核解释它的意义。

### 1.3 与闲暇的关系

`idle`（闲暇时长）同时是两件事：

1. 时钟的一个字段（角色知道现在有多闲）
2. **记忆整理的触发条件**（见下）

这一个字段兼任两个职责，是「不需要 cron」的原因。

## 二、D5 · 记忆整理由「闲暇」触发，不由时间触发

### 2.1 两种视角

| 视角 | 做法 |
|---|---|
| 工具视角 | cron 定时任务 |
| **角色视角** | **注意力队列为空 + 当前会话静默超过阈值 → 发呆 → 唤起 DSH 整理** |

### 2.2 为什么角色视角更好

- 与单注意力模型是同一个模型的自然产物，不是额外模块
- 天然产生「今天很忙没空回想 / 今天很闲想了很多」的差异——定时器给不了这个

### 2.3 闲暇动作必须可中断

整理由独立的**整理会话**执行（详见 05 的 4.4 节）。它必须满足：

| 要求 | 说明 |
|---|---|
| **可中断** | 中途来消息 → 立即让位 |
| **可续** | 未完成的整理进度不丢 |

「可中断」比「可续」更重要。否则角色会因为「正在回想」而不理人——**人被打断时会应你，不会说「等我想完」**。

## 三、时间感为什么是角色的必要条件

回顾 D2：串行 = 真实的经历顺序 = 时间存在的前提。

一个并行处理所有会话的角色没有「此刻」，因为所有的时刻同时发生。没有此刻，就没有：

- 等待（「你说要查，我等了五分钟」）
- 遗忘（「上次聊这个是很久以前了」）
- 重逢（「好久没说话」）
- 错过（「昨天那个事我今天才看到」）

时钟提供数据，串行提供顺序，两者合起来才是时间感。
