> 状态：**架构定稿**（2026-10-23），下一步进入实现。只记录不变式、决策与待办。

## 一、这是什么

为「数字生命」体系做顶层设计的文档集，目标是一个**主体**而非更好的机器人。唯一判据：**关掉所有渠道后，它是否还存在、是否还在变化。** 渠道只是接触世界的窗口，记忆按天／周／月／年计，迁移打包整个角色目录。逐项对照见 [总览-一页版](总览-一页版.md)。

## 二、移交包里有什么

`架构探索/`：README（本文）、总览-一页版、设计文档 01–30（按编号读）、refs/。同级 `probes/`：`result.yaml`（**所有实测结论的唯一真源**）、restart-checklist.md、p*.mjs（可复跑探针）。

**设计**（01–30）说我们认为应该怎样；**证据**（`result.yaml`）说我们试过确实可以／确实不行。设计可以改，实验数据不会变。

## 四、实验结论（截至 2026-10-23）

十二个探针：**十项通过、一项部分、一项用户确认后免测**。

| 编号 | 验证什么 | 结果 |
|---|---|---|
| P0 | 鉴权能否离线完成 | ✅ |
| P1 | 同 session 上下文延续 | ✅ |
| P2 | 人格注入点在哪 | ✅ 配置级（preset） |
| P3 | 压缩归谁管、可不可控 | ✅ 在 HTTP 代理层 |
| P4 | 文件权限边界 | ✅ 用户确认（区内读写／区外只读） |
| P5 | 人格是否真的生效 | ✅ |
| P6 | session 间上下文隔离 | ✅ 用户确认 |
| P7 | 重启后 session 是否恢复 | ✅ 29/29 存活 |
| P8 | `complete` 开关行为 | ✅ |
| P9 | 每角色独立工作区 + 投递 | ✅ |
| P10 | DSH 能否在工作区写文件 | ✅ |
| P11 | 实时取回复的通道 | 🟡 `/stream` 未查明，PoC 用文件轮询 |

架构假设无一条被推翻；唯一修正是 `05` 的「一次同步往返」实为异步投递。未验证项只剩 **T7**，证据见 [`probes/result.yaml`](../probes/result.yaml)。

## 六、讨论原则

1. 从「角色」出发定约束，不从「工具 / 服务」出发。
2. 先定不变式再定机制；违反不变式的设计一律否决。
3. 可判断的交给判断，不可判断的交给规则。
4. **自研的是骨头，推荐的是家具**。

## 七、文档维护约定

- 一个主题一个文件；编号全局唯一（I / D / T / P），跨文件引用直接写编号。
- 结论优先；**不留两份真源**——内容迁移后旧文件不再是正式内容。
- **被取代的文档移入 `_archive/`，不要直接删除**。
- 跨文档引用写章节标题，不写编号——编号会漂移，标题不会。
- **数值结论必须带环境标签**（token 数、窗口、延迟 + 测时环境）。
