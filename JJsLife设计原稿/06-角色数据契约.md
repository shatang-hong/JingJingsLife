## 一、第一刀：三类数据，只有一类是「角色」

这一刀决定了「打包带走」到底带走什么。

| 类别 | 内容 | 可迁移 | 归谁 |
|---|---|---|---|
| **本体** | 人格、记忆、知识、关系、安全基线 | ✅ 是角色的定义 | 内核所有，DSH 写 |
| **运行状态** | 实时记忆、时钟、注意力、session 映射 | ❌ 换环境即失效 | 内核 |
| **渠道绑定** | 账号、白名单、token、路由配置 | ❌ 属于渠道，不属于角色 | 适配层 |

原则：

> **打包角色 ≠ 打包一切。** 带走的是「它是谁」，不是「它此刻在做什么」。

**实时记忆不迁移的理由**：它是工作台，不是记忆。搬到新环境后，「刚才在 A 群，有件事没说完」这条状态已经过期了，带过去反而会造成行为错乱。

## 二、目录布局

```
character/
├── identity/                 # 本体 · 身份层
│   ├── manifest.json         # 格式版本、创建时间、迁移记录
│   ├── baseline.md           # L0 安全基线（不可变）
│   ├── core.md               # L1 身份内核（不可替换，仅管理员手工改）
│   └── persona.md            # L2/L3 人格与观念（DSH 可写，须过校验）
│
├── memory/                   # 本体 · 长期记忆（详见 10）
│   ├── core/                 # 角色自我认知、重大事件
│   ├── people/<id>/          # 按人
│   ├── groups/<id>/          # 按群
│   ├── topics/<topic>/       # 按主题
│   ├── journal/              # 周记 / 月报
│   └── archive/              # 归档（按时间）
│
├── knowledge/                # 本体 · 知识
│   ├── sources/              # 原始文档
│   └── notes/                # 沉淀笔记
│
├── media/                    # 媒体文件（内容寻址，详见 16）
│
├── assets/stickers/          # 表情库
│
├── relations/                # 本体 · 关系网络（详见 07、15）
│   ├── nodes/person|group/   # 节点（真源）
│   ├── graph.jsonl           # 节点之间的边（真源）
│   ├── _schema.yaml          # 维度定义（详见 09）
│   ├── _index.json           # 索引（派生）
│   └── _index.md             # 管理者视图（派生）
│
├── runtime/                  # 运行状态（不迁移）
│   ├── realtime.log          # 实时记忆（append-only）
│   ├── clock.json            # 时钟状态
│   └── attention.json        # 注意力状态
│
└── sessions/                 # DSH session 映射（不迁移）
```

### 工作区之外：DSH 只读不可写

```
character-ops/                # ← 必须放在工作区**之外**
├── audit/                    # 安全审计（不记原文）
├── logs/trace/               # 链路追踪（滚动）
└── snapshot/                 # 快照
```

> **为什么必须移出去**：DSH 对工作区内可读**可写**，对工作区外可读但**不可写**（见 [02](02-决策记录.md) 的 D4.1）。
> 这三个目录只要留在 `character/` 里，DSH 就能改审计、删快照。移出去之后写保护才成立。
>
> 读保护做不到——所以策略是**内容不敏感**：审计不记原文，快照只是历史版本。

### 为什么 relations 单独一层，不并入 memory/people

| 路径 | 是什么 |
|---|---|
| `memory/people/<id>/` | **事件流水**（发生过什么） |
| `relations/nodes/person/<id>.md` | **当前状态**（现在是什么关系） |

混在一起会导致每次读关系都要扫全量流水。

## 三、载体格式：md 与 json 的分界

不要教条地「一切皆 md」。

判据是**给谁看**：

| 格式 | 适用 | 判据 |
|---|---|---|
| **md** | 人格、记忆、知识、关系描述 | 需要人和模型都读懂、需要可编辑 |
| **json** | 时钟、注意力、映射、清单、索引 | 机器状态，人不需要逐字读 |

还有一个**隐藏理由**：

> 如果把时钟、注意力也写成 md，模型会倾向去「编辑」它们——而它们不该被模型编辑。

**格式本身就是权限暗示。可读的文本会被当作可改的。**

## 四、快照

> **不依赖 `dsh-rewind`。** 它做的是「对话回退」（DSH 会话的事），本文做的是「角色文件版本」（角色载体的事）。
> 但可以借鉴它的两条思路：**写前备份、不变不存**。

### 4.1 快照什么

| 对象 | 范围 | 时机 |
|---|---|---|
| `identity/persona.md` | 单文件 | 每次写入前 |
| `identity/core.md` | 单文件 | 每次写入前（理论上永不触发） |
| `identity/baseline.md` | 单文件 | 每次写入前（理论上永不触发） |
| `relations/nodes/**/*.md` | 单文件 | 每次写入前 |
| `memory/core/*` | 单文件 | 每次写入前 |
| 其余记忆 | 不单独快照 | 靠追加天然可回溯 |
| **整个 character/** | 目录级 | 每日一次 |

**为什么不每次全量快照**：记忆目录可能很大，每次写入都全量复制不可持续。

- 单文件快照 → 覆盖「写坏了某个文件」这个主要风险
- 目录级每日快照 → 覆盖「大面积损坏」

### 4.2 快照的内容

```
snapshot/<file-path>/<timestamp>.md     # 原内容
snapshot/<file-path>/<timestamp>.meta   # 谁改的、何时
```

**变更理由不放在 meta 里，而放在 md 文件自身的头部。**

理由只有 DSH 知道，让它在写文件时顺带写一行，比让内核去猜便宜得多。

### 4.3 两条安全要求

1. **快照目录放在工作区外**（`ops/snapshot/`），DSH 只读不可写——它能读到，但删不掉、也改不了。
   读保护做不到，所以真正的防线是「快照只是历史版本，被读到等于读到历史」。见 [02](02-决策记录.md) 的 D4.1。
2. **回滚由内核执行**，不需要 DSH 参与——回滚是管理员动作，不是角色的行为。

### 4.4 回滚粒度

| 粒度 | 场景 |
|---|---|
| 单文件回滚 | 日常（某个文件改坏了） |
| 整体回滚 | 紧急（基线被篡改、大面积损坏） |

### 4.5 `format_version` 必须现在就有

哪怕恒为 `1`。第一次改格式时若无依据字段，迁移无从下手。

这是典型的「现在不做，以后无解」。

## 五、导出契约

| 项 | 默认 | 可选 |
|---|---|---|
| identity / memory / knowledge / relations | ✅ 导出 | — |
| **assets/**（表情库等表达资产） | ✅ 导出 | — |
| runtime / sessions / logs | ❌ | — |
| 渠道配置 | ❌ | — |
| **media/**（原始图片、语音） | ❌ | ✅ 用户可选 |
| **审计日志** | ❌ | ✅ 用户可选 |

**`assets/` 与 `media/` 的区别**：

| | 属于什么 | 为什么 |
|---|---|---|
| `assets/stickers/` | **本体** | 「它会用哪些表情」是它的表达方式，换环境应该还在 |
| `media/` | **运行状态** | 原始像素是临时数据，且体积大；记忆里保留的是描述（见 16） |

**审计日志为什么可选**：它属于内核视角的运维数据，不是角色本体。但对使用者可能有价值（看自己的角色被拦过多少次、都是什么类别），所以默认不带、允许显式勾选。

注意：审计日志本就不记原文，因此导出的是**拦截事件元数据**，不是内容——这也保证导出包不会因为附带审计而变成敏感数据包。

### 导入时必须验证

1. `format_version` 兼容性
2. `baseline.md` 是否被篡改
3. 是否存在越权路径引用（`../` 之类）

第三条容易被忽略——角色包是可分享的，别人给的包可能带着路径穿越。
