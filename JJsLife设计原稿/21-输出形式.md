# 21 · 输出形式

> 上游：[09-人格侧面投影](09-人格侧面投影.md)｜ [16-多模态消息](16-多模态消息.md)

## 一、为什么「说什么」不够

09 管**内容约束**（私事、玩笑）；**形式是「像人」的另一半，更易露馅**。

## 二、六个参数，分两类

长度、分段、延迟、表情密度随**关系档位**变（表情密度见 16 的 6.3）；标点风格、语气词随**人格**变。

> **随场合变的是「分寸」，角色固有的是「口音」。**

## 三、延迟：最大的「人味」开关

总延迟 = 打字时间 + 斟酌时间 + 抖动；打字时间 = 字数 × 每字耗时（80–150ms/字）；斟酌时间随 `formality` 单调递增；抖动随机 ±30%。

**很熟的人快**，**正式 / 上级慢**，**陌生人中等**。

| 情况 | 处理 |
|---|---|
| 计算值 > 8 秒 | 折叠为「正在输入」后按时长发送 |
| 计算值 > 30 秒 | 放弃延迟立即发送（避免以为掉线） |

> **延迟是为了像人，不是为了折磨人。**

## 四、分段：多条短气泡比一大段更像人

| 条件 | 行为 |
|---|---|
| 总字数 ≤ 30 | 一条发完 |
| 30–80 | 拆 2 条（按句号 / 问号） |
| > 80 | 拆 2–3 条，不拆更多 |

**正式**少拆，**中性**中等，**随意**多拆。优先在 `。！？` 处断，其次 `，`，**不在词中间断**；每条都要**独立成立**。

## 五、长度

长度是 `formality` + 话题性质的产物：群聊接话 5–20 字；私聊闲聊 10–50 字；正式答复 / 解释不限但要有结构；表达情绪 1–5 字或一个表情。

**硬规则：不要每次都写满**——人常只答一半。

## 六、标点与语气词：属于人格，不属于场合

句末不加句号（「好呀」而非「好呀。」）、爱用省略号、不用感叹号、常用语气词 啊 / 吧 / 呢 / 哈——全部归 `persona.md`，**不随场合变**，由 DSH 演化。

## 七、落地：一条输出规格

内核在 `deliver` 时附带 `output_spec`（05 的 2.1），DSH 按它组织输出：

| 字段 | 含义 |
|---|---|
| `max_chars` | 建议上限 40，非硬限制 |
| `segments_hint` | 建议分 2 条 |
| `sticker_density` | 表情密度：中 |
| `delay_ms` | 延迟区间 1200–2600 |
| `style` | persona 风格：句末句号 false、感叹号 rare、语气词 呀 / 吧 / 哈 |

给「建议」不给「硬限制」，因为**内容优先级高于形式**：说清楚而 40 字装不下时就该超。

> **形式服务于表达，不能反过来。**

| 参数 | 谁生成 | 谁执行 |
|---|---|---|
| `max_chars` / `segments_hint` | 内核（按关系档位） | DSH（生成时遵守） |
| `delay_ms` | **内核** | **适配器**（照做，不自行调整） |
| 标点 / 语气词 | 人格 | DSH |

> **适配器不决定节奏，只执行节奏。**

渠道只知道「怎么发」，不知道「该等多久」（23 的 4.2）。

## 八、PoC 范围

| 能力 | PoC |
|---|---|
| 延迟（打字感） | ✅ 成本极低、效果最明显 |
| 分段（多气泡） | ✅ |
| 长度建议 | ✅ |
| 标点 / 语气词 | ✅ 写进 persona 即可 |
| 「正在输入」状态 | ⭕ 取决于渠道是否支持 |


## 九、未决

1. **延迟的真实感**：模拟打字会不会因太规律而显得假？是否要引入「读消息时间」？
2. **多气泡的间隔**：相邻两条之间要不要停顿？
3. **分段的方言差异**：QQ 长文、微信短句不同，是否按渠道区分？
4. **被打断时的输出**：分段发送中途来了新消息，剩下的还发吗？
5. **长度建议的校准**：40 字这个值需要真实数据验证。
